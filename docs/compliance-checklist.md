## 2. 隐私接口清单（实测）

2026-10-10 对 `miniprogram/` 全量扫描 `wx.*` 调用，实际使用 **10 个 API**：

| API | 用途 | 是否涉及个人信息 |
| --- | --- | --- |
| `wx.getStorageSync`、`wx.setStorageSync` | 本地收藏读写 | 否，仅本机存储 |
| `wx.navigateTo`、`wx.redirectTo`、`wx.navigateBack`、`wx.switchTab` | 页面跳转 | 否 |
| `wx.showToast` | 操作反馈 | 否 |
| `wx.getWindowInfo`、`wx.getDeviceInfo`、`wx.getMenuButtonBoundingClientRect` | 自定义导航栏布局 | 否，只读设备与窗口尺寸，不落盘、不上传 |

**零命中的接口**：`wx.request`、`wx.uploadFile`、`wx.downloadFile`、`wx.connectSocket`、`wx.getLocation`、`wx.getUserProfile`、`wx.getUserInfo`、`wx.login`、`wx.requirePrivacyAuthorize`。

**结论** [已核实事实]：V1.0 无网络请求、无位置、无用户信息、无登录、无支付、无广告。

**派生后果** [技术建议]：

- 后台「服务器域名 / request 合法域名」无需配置。
- 隐私说明可以写得很短（见第 5 节），且**不需要**授权弹窗。
- 但"代码不收集"不等于"后台表单不用填"——是否需要提交《用户隐私保护指引》以及如何填写，必须在提审日按后台实际要求复核，不在此处下结论。 [待确认]

## 6. 内容合规

### 6.1 红线与代码侧落地证据

| 风险 | 控制要求 | 代码侧证据 |
| --- | --- | --- |
| 封建迷信（算命、改运、消灾、灵验） | 全部禁止 | 文案与页面无此类表达 |
| 结果保证（"最佳吉日""必成"） | 禁止星级、百分比、吉凶分 | 规则不计算吉凶分、不按命中条数排序，结果只按日期升序 |
| 个性化命理（八字、生肖、姓名推结果） | 不收集、不提供 | 无相关输入项；`getEightChar` 等命理 API 禁止进入业务路径 |
| 第三方库宜忌混入 | 宜忌只能来自自校勘的 `verified` 规则包 | 库内 `getDayYi` / `getDayJi` / 吉神凶煞 / 黄黑道 / 法定节假日 / 节日数据全部禁止，业务路径零命中 |
| 事项越权开放 | `reviewing` / `unsupported` 必须置灰且不可触发查询 | 可查询四事项为 `travel`、`relocation`、`opening`、`marriage`（均 `limited`）；`moving-in` 为 `reviewing`、`funeral` 为 `unsupported`。门禁只在 `data/event-types.ts` 的 `canQueryEventType()` 一处 |
| 把部分收录说成完整结论 | `partial` 事项需在事项入口、结果列表上方、详情页规则区三处显示覆盖范围 | **三处均已落地**，见 6.2；由 `tests/event-types.test.ts`「覆盖范围披露」一组用例守住 |
| 冲突日期凭空消失 | 冲突必须逐日列出并可查双方依据 | `findDates` 返回 `conflictDates` 而不只是计数；冲突日返回 `unresolved`（对应卷十常例"两者皆不注"） |
| 来源误导 | 不把库内宜忌称为《协纪辨方书》 | 详情页每个宜忌标签可展开到 `verified` 规则与来源定位；来源登记见 `docs/sources-ledger.md` |
| 数据缺失时硬出结果 | 宁可不出结果 | 区分"无数据 / 无匹配 / 有明确排除"三种语义；错误码沿用方案 5.9 |

### 6.2 覆盖范围披露落点（2026-10-10 复查，缺口已补）

项目自定的红线要求"`limited` 事项的结果不得呈现为完整传统结论：事项入口（chip 标记 + 选中提示）、结果列表上方、详情页规则区三处都必须显示覆盖范围"。首轮核对时只满足一处，同日补齐，现状如下：

| 要求位置 | 代码落点 | 实测结果 |
| --- | --- | --- |
| 事项入口 chip 标记 | `find-date.ts` 用 `getStatusBadgeText(entry.status)` 生成 `badgeText`，`find-date.wxml` 渲染 `event-chip__badge` | ✅ 可查询的四个事项都显示「有限收录」，与古籍用语同行显示 |
| 事项入口选中提示 | `find-date.ts` 选中时把 `entry.statusNote` 写进 `scopeNoteText`，`find-date.wxml` 渲染 `scope-note` | ✅ 四个事项各说自己的收录边界 |
| 结果列表上方 | `applyOutcome()` 取 `rulePack.completeness`，partial 时在汇总卡里显示披露 | ✅ 用统一的 `PARTIAL_COVERAGE_NOTICE`，不再只有"计算失败／没有找到"两类 |
| 详情页规则区 | `day-detail.ts` 每个事项的 `RuleSectionViewModel` 带披露语与收录范围，与逐条依据同屏 | ✅ partial 时显示 `PARTIAL_COVERAGE_NOTICE` ＋ 该包的 `coverage` 全文 |

**统一出口**：`data/rules/manifest.ts` 的 `describeCoverage(completeness, coverage)` 是唯一入口，partial 与 complete 的分支集中在一处，不再有"某个页面多一句免责话"的可能。原先零引用的 `PARTIAL_COVERAGE_NOTICE` 与 `travel.statusNote` 都已接入。

**测试守则**：`tests/event-types.test.ts` 的「覆盖范围披露」一组用例覆盖三件事——partial 一律给出统一披露语、四个可查询事项都拿得到披露语、三处落点在页面视图模型与 wxml 绑定上都在。页面模块用 `vi.stubGlobal` 接住全局 `Page()`／`Component()` 后取回视图模型断言。

**仍未做**：真机与开发者工具里的视觉回归（新增的 chip 短标记与两处色块会改变版面）。归入 D 类待办。

**规则级适用边界与首页范围说明（2026-10-10 补）**：详情页规则卡展开区新增「适用范围与限制」，把每条规则的 `limitations` 与出处同屏显示（`day-detail.ts` 的 `RuleDisplayItem.limitations`，`tests/day-detail-context.test.ts` 守这条）——此前 `limitations` 由服务层返回但没有任何页面渲染，而规则包 1.17.1 的变更记录已按"会直接显示在日期详情页"改写措辞。首页「今日宜忌」区块同时补一行收录范围说明（`almanacScopeText`），按事项表动态生成，避免把「今天只有一行忌」读成「其余事项都没问题」。

## 11. 审核说明（草稿） [技术建议]

提交审核时使用，需在提审日按当时的后台表单调整。

> **产品性质**：本小程序是一款传统历法与民俗文化查询工具，提供公历、农历、二十四节气、干支与节日的对应查询，以及基于已校勘古籍规则的传统日期参考。
>
> **不包含的内容**：不提供八字算命、运势预测、改运、消灾、祈福、法事等命理或宗教服务；不收集用户个人信息；不提供付费服务，无广告，无诱导分享。
>
> **找日子功能说明**：本版本开放"出行、搬家、开业、婚嫁"四个事项，规则分别来自《钦定协纪辨方书》卷十一「行幸遣使（出行同）」「般移（移徙同）」「开市」「嫁娶」条目，逐条对照影印本录入并附来源。四个条目都还有未能判定或尚未实现的适用边界，结果页面在事项入口、结果列表上方与详情页规则区三处标注收录范围，不代表完整的传统规则结论。其余事项（入宅、安葬）资料仍在整理中，入口置灰且不可触发查询，**不会以任何方式给出结论**。
>
> **数据说明**：全部计算在本机完成，不向服务器发送任何数据；收藏只保存在本机存储中。日历数据以国家标准 GB/T 33661—2017 与中国科学院紫金山天文台资料校核，交叉参考香港天文台对照表。
