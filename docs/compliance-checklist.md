## 2. 隐私接口清单（实测）

2026-10-19 对 `miniprogram/` 的 TypeScript 源码复扫 `wx.*` 调用，为 **12 个 API**；另有只返回公开日期的 `onShareAppMessage` 回调及 `getCurrentPages` 页面栈读取，不计入 `wx.*` API 数量：

| API | 用途 | 是否涉及个人信息 |
| --- | --- | --- |
| `wx.getStorageSync`、`wx.setStorageSync` | 本地收藏及首次说明确认标记读写 | 否，仅本机存储 |
| `wx.navigateTo`、`wx.redirectTo`、`wx.navigateBack`、`wx.switchTab` | 页面跳转 | 否 |
| `wx.showToast` | 操作反馈 | 否 |
| `wx.showModal` | 首次查询时展示完整版使用说明 | 否 |
| `wx.setClipboardData` | 用户主动复制公开的文献来源链接 | 否；不读取剪贴板 |
| `wx.getWindowInfo`、`wx.getDeviceInfo`、`wx.getMenuButtonBoundingClientRect` | 自定义导航栏布局 | 否，只读设备与窗口尺寸，不落盘、不上传 |

**零命中的接口**：`wx.request`、`wx.uploadFile`、`wx.downloadFile`、`wx.connectSocket`、`wx.getLocation`、`wx.getUserProfile`、`wx.getUserInfo`、`wx.login`、`wx.requirePrivacyAuthorize`。

**代码事实**：业务源码未见网络请求、定位、用户资料读取、登录、支付或广告接口；历法与规则本地计算。主动分享由微信平台处理，不能把「业务代码无请求」写成平台也不处理任何数据。

**派生后果** [技术建议]：

- 后台「服务器域名 / request 合法域名」无需配置。
- 隐私说明可以写得很短（见第 5 节），且**不需要**授权弹窗。
- 但"代码不收集"不等于"后台表单不用填"——是否需要提交《用户隐私保护指引》以及如何填写，必须在提审日按后台实际要求复核，不在此处下结论。 [待确认]

## 3. 本地存储清单（实测）

| 存储键 | 内容 | 是否上传 | 清理行为 |
| --- | --- | --- | --- |
| `syliangchen:favorites:v1` | 收藏项：`dateKey`、`createdAt`、`calendarDataVersion`；外层带 `schemaVersion` | 否，只写当前设备的小程序存储 | 读取失败或 schema 不识别时**保留原值、不清空**；上限 200 条 |
| `syliangchen:disclaimer:v1` | 首次查询完整版说明的确认标记 `accepted` | 否，只写当前设备的小程序存储 | 读写失败时本次确认仍可查询，下次再次提示；未知值不覆盖 |

收藏不包含任何个人身份信息，不含查询历史，不含设备信息。删除小程序或清理缓存会一并清除，且不跨设备同步——这一点**必须写进隐私说明**（见第 5 节）。

### 6.2 覆盖范围披露落点（2026-10-10 复查，缺口已补）

项目自定的红线要求"`limited` 事项的结果不得呈现为完整传统结论：事项入口（chip 标记 + 选中提示）、结果列表上方、详情页规则区三处都必须显示覆盖范围"。首轮核对时只满足一处，同日补齐，现状如下：

| 要求位置 | 代码落点 | 实测结果 |
| --- | --- | --- |
| 事项入口 chip 标记 | `find-date.ts` 用 `getStatusBadgeText(entry.status)` 生成 `badgeText`，`find-date.wxml` 渲染 `event-chip__badge` | ✅ 六个事项 2026-10-12 改判 `supported` 后不再显示标记；标记逻辑仍在，将来出现 `limited` 事项会自动生效 |
| 事项入口选中提示 | `find-date.ts` 选中时把 `entry.statusNote` 写进 `scopeNoteText`，`find-date.wxml` 渲染 `scope-note` | ✅ 六个事项各说自己的收录边界（`supported` 后改述为收录范围与边界，文案仍有） |
| 结果列表上方 | `applyOutcome()` 取 `rulePack.completeness`，partial 时在汇总卡里显示披露 | ✅ 用统一的 `PARTIAL_COVERAGE_NOTICE`，不再只有"计算失败／没有找到"两类 |
| 详情页规则区 | `day-detail.ts` 每个事项的 `RuleSectionViewModel` 带披露语与收录范围，与逐条依据同屏 | ✅ partial 时显示 `PARTIAL_COVERAGE_NOTICE` ＋ 该包的 `coverage` 全文 |

**统一出口**：`data/rules/manifest.ts` 的 `describeCoverage(completeness, coverage)` 是唯一入口，partial 与 complete 的分支集中在一处，不再有"某个页面多一句免责话"的可能。原先零引用的 `PARTIAL_COVERAGE_NOTICE` 与 `travel.statusNote` 都已接入。

**测试守则**：`tests/event-types.test.ts` 的「覆盖范围披露」一组用例覆盖三件事——partial 一律给出统一披露语、每个可查询事项都拿得到披露语、三处落点在页面视图模型与 wxml 绑定上都在。页面模块用 `vi.stubGlobal` 接住全局 `Page()`／`Component()` 后取回视图模型断言。

**本轮验证边界**：六个当前开放事项的模拟器查询与主要布局已验证；`partial` 的临时展示仍主要由单测覆盖，未用真实事项改状态做视觉测试。真机本轮由用户明确跳过，见 [发布检查单](release-checklist.md)。

**规则级适用边界与首页范围说明（2026-10-10 补）**：详情页规则卡展开区新增「适用范围与限制」，把每条规则的 `limitations` 与出处同屏显示（`day-detail.ts` 的 `RuleDisplayItem.limitations`，`tests/day-detail-context.test.ts` 守这条）——此前 `limitations` 由服务层返回但没有任何页面渲染，而规则包 1.17.1 的变更记录已按"会直接显示在日期详情页"改写措辞。首页「今日宜忌」区块同时补一行收录范围说明（`almanacScopeText`），按事项表动态生成，避免把「今天只有一行忌」读成「其余事项都没问题」。
