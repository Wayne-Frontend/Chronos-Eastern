# 宜忌冲突裁决审计（《协纪辨方书》卷十）

> 审计日期：2026-10-09（Asia/Shanghai）
> 审计对象：`xjbf-travel` 规则包中"纳入与排除同级命中"（`unresolved`）的裁决依据
> 审计边界：只核对《协纪辨方书》卷十「宜忌」对**吉凶并见**给出的取舍规则，以及它能否、应否被本项目实现。本文不修改业务代码或规则数据。

## 1. 结论摘要

1. **原书明确反对"任一忌覆盖任一宜"。** 卷十篇首批评旧历「凡吉神所宜之事，一遇凶煞则无论轻重而概忌之，尤为未当」。本项目把"忌优先"当默认语义是错的，把冲突日判为 `unresolved` 反而是**正确的保守做法**。
2. **卷十的常例正是"互相不注"**：影印本第 140 帧「凡所忌者則不注宜，所宜者亦不注忌，不與德合併，如常例」。即宜忌并见且无德神介入时，宜、忌**同时不生效**。这与我方 `unresolved`（该日不进入结果）语义一致，不是权宜之计。
3. **例外由德神触发，但形制复杂**：与天德／月德／天德合／月德合并临时，忌会被削减为一份**剩余清单**（第 140 帧「止忌安撫邊境選將訓兵出師求醫療病，餘皆不忌」），且「如遇德犹忌之日则仍注忌」——德并非万能。
4. **裁决在原理上可判定，但需要一件本项目尚未录入的文物**：卷十末尾的**宜忌等第表**（影印本第 222 帧起）。它是一张「忌神煞 × 六等第」的矩阵，单元格以「某月＋某建除日」定位，配合平日条下的六等第定义使用。
5. **等第表覆盖不了本项目的一部分冲突。** 「巳日」不在卷十的忌项清单中（卷十忌项不含巳日），它是卷十一「行幸遣使」条目自带的日支忌。因此"天喜（成日，宜）撞巳日（忌）"这类冲突**不在卷十裁决体系的射程内**，即使录入等第表也无解。
6. **建议：本版维持 `unresolved`，不实现六等第。** 理由见 §6：射程不全、录入成本高、且需要规则引擎新增一类"跨条件裁决"能力。当务之急是把冲突的**原因**按卷十的常例如实讲清楚，而不是急着替用户下结论。

## 3. 卷十的裁决体系

### 3.1 篇首立场：反对一概以忌压宜

转录所记篇首大意：神煞之宜忌各随其性，力有相胜则情随力变；旧历「凡吉神所宜之事，一遇凶煞则无论轻重而概忌之，尤为未当」。

### 3.2 六等第（平日条下，转录）

| 等第 | 原文 | 结果 |
| --- | --- | --- |
| 上吉 | 足胜凶 | 从宜不从忌 |
| 上次吉 | 足抵凶 | 遇德从宜不从忌；不遇从宜亦从忌 |
| 中等 | 吉不抵凶 | 遇德则吉胜，从宜不从忌；不遇从忌不从宜 |
| 中次 | 凶胜于吉 | 遇德始相抵，从宜亦从忌；不遇从忌不从宜 |
| 其下 | 凶又逢凶 | 遇德从忌不从宜；不遇诸事皆忌 |
| 最下 | 凶叠大凶 | 遇德仍诸事皆忌 |

并注明「除建破等日条例简易及专忌之日无庸分别外，餘分为六等」。**建日、破日等不参与六等第分级**——这与本项目现有冲突直接相关：月破类冲突不落在这套分级内。

### 3.3 常例：并见即两不注（影印第 140 帧）

> 凡所忌者則不注宜，所宜者亦不注忌，不與德合併，如常例。

即：在**没有德神介入**的默认情形下，宜与忌同时失效。这就是本项目的 `unresolved`。

### 3.4 例外：德合并临（影印第 140 帧）

德合并临时，忌被削减到一份剩余清单，其余不再计忌：

> 寅申巳亥月值相日，亥月又值時德，六合止忌安撫邊境選將訓兵出師求醫療病，餘皆不忌。申月值月害與天德、月德合併，亦止忌安撫邊境選將訓兵出師求醫療病，餘皆不忌。

两个要点：

- 剩余清单是**逐月、逐神煞、逐用事**的，不是一条通则；
- 「如遇德猶忌之日則仍註忌」（第 228 帧）——存在德也压不住的专忌。

### 3.5 天赦、天愿的特殊地位（影印第 100 帧）

> 天赦、天願皆合干支取義，其氣純，其力大，乃日之最吉者，能解諸凶，故特表之。

这条支持一个方向：**天赦日遇忌时，宜可能压过忌**。但它给的是定性表述，没有给出"解诸凶"的边界（哪些忌能解、哪些不能），单凭本帧不足以直接编码。

### 3.6 宜忌等第表（影印第 222 帧）

表体为矩阵：列头是忌方神煞（月煞、月刑、月害、月厭、大時、天吏等），行是六等第，单元格以「某月组＋某建除日」定位，例如月厭列下见「寅申月　破日」「巳亥月　滿日」，月害列下见「子午月　閉日」。

**该表的输入恰好是本项目已具备的事实**（节令月支 + 建除），因此原理上可计算。但它跨多帧、覆盖约五十个忌神煞，且需与 §3.2 的分级、§3.4 的德合判定合用。

## 4. 与本项目现状的对照

| 卷十的规定 | 本项目现状 | 判断 |
| --- | --- | --- |
| 反对"忌一概压宜" | 引擎不设忌优先，同级命中返回 `unresolved` | 一致 |
| 常例"宜忌两不注" | `unresolved` 日不进入结果，仅计数 | **一致** |
| 德合并临则忌削减 | 未实现 | 缺口 |
| 六等第分级取舍 | 未实现 | 缺口 |
| 天赦"能解诸凶" | 未实现，天赦遇忌仍判 `unresolved` | 缺口（偏保守） |
| 建破等日"条例简易"不参与分级 | 月破冲突同样返回 `unresolved` | 一致（本就不该套分级） |

结论：**现有的 `unresolved` 不是权宜之计，而是与原书常例相符的默认语义。** 缺口在于原书给出的若干例外（德合、天赦），本项目一律按常例处理，因而偏保守——会少给一些日期，但不会给出原书未支持的结论。

## 5. 可裁决性的两个硬缺口

### 5.1 射程不全：巳日类冲突不在卷十体系内

卷十的忌项清单不含「巳日」。巳日来自卷十一「行幸遣使（出行同）」条目自身的忌项，属**用事自带的日支忌**，不属于卷十按神煞分级的对象。

因此本包已有的这类冲突——天喜（成日，宜）撞巳日（忌）、吉期（除日，宜）撞巳日（忌）——**即便完整录入等第表也无法裁决**，除非卷十一自身或别处另有说明。当前样本中这类冲突占比不低。

### 5.2 形制不匹配：需要"跨条件裁决"能力

现有规则 DSL 的 `when.all` 是合取式，`evaluateDay` 也只做"逐条求值再按同级冲突分类"。六等第要求的是**在冲突发生之后，再按（月支，建除日，涉及的神煞集合）查表定等**，属于对冲突结果的二次裁决，不是单条规则能表达的条件。

实现它意味着在规则引擎里新增一类裁决层，并按 §3.6 录入矩阵数据。这是比第三阶段那次 DSL 扩展大得多的改动，且会引入一份**未经本项目逐格核对**的表格。

## 6. 建议

1. **本版维持 `unresolved`，不实现六等第。** 它符合原书常例；在射程不全（§5.1）与形制不匹配（§5.2）两个问题解决前强行实现，只会得到一份"部分日子按新法、部分日子按旧法"的混合语义，比现在更难解释。
2. **把冲突原因按卷十常例如实讲给用户**，而不是让它显得像缺陷。当前找日子页已列出冲突日期并可跳详情；详情页的措辞可再补一句依据：宜忌并见且无德神裁决时，原书常例即两不注。
3. **若将来要实现，顺序应是**：先补齐三十二项原语 → 再逐格核对并录入宜忌等第表 → 先只实现德合并临这一条例外（它的输入是节令月支与日干支，本项目已具备）→ 最后才考虑六等第。**天德仍是 B 类**（四仲月以乾坤艮巽记位），在它定案之前，德合例外无法完整实现。
4. **`unresolved` 的计数与清单要继续保留**，它是这套保守语义可被用户检验的唯一出口。

## 7. 审计范围限制

- 本文核对的是卷十对**吉凶并见**的取舍规则及其可实施性，**没有**转录宜忌等第表的全部单元格，也没有核对铺注条例中与"出行"直接相关的条目是否单列。
- 卷十篇首、六等第、铺注条例的措辞本轮以转录为准；常例句、德合句、天赦句、等第表与铺注条例的存在与形制已回看影印。**转录与影印若有出入，以影印为准**，本表尚未逐字校对全部上述转录句。
- 本文不构成实现授权。任何据此改动的规则必须另走影印核对、来源登记与测试流程（方案 6.8）。
- 本节结论不改变项目的产品定位：即便裁决完善，也只输出文化参考，不作现实安排结论。
